## คำสั่งที่ใช้จริง

ทุกคำสั่งรันจากโฟลเดอร์ `backend`

### 1. ดูการเปรียบเทียบทั้งหมด (ใช้ตอนนำเสนอสด)

```bash
./.venv/bin/python ml_baseline/compare_demo.py \
    --data ml_baseline/PhiUSIIL_Phishing_URL_Dataset.csv \
    --flip-label --pause
```

เดินให้ดู 5 ขั้น หยุดรอกด Enter ระหว่างขั้น
ออกไฟล์ `ผลเปรียบเทียบอัลกอริทึม.xlsx` กับ `.png`

ตัด `--pause` ออกถ้าไม่ได้นำเสนอ · เติม `--sample 40000` ถ้าอยากให้เร็ว (ราว 20 วินาที)

### 2. สร้างตัวเลขในหน้าเว็บสาธิตใหม่

```bash
./.venv/bin/python ml_baseline/build_demo.py \
    --data ml_baseline/PhiUSIIL_Phishing_URL_Dataset.csv \
    --flip-label --page ../demo-compare.html
```

จะพิมพ์ตารางออกมาก่อนเขียนไฟล์ ใช้ตรวจว่าตัวเลขตรงกับที่หน้าเว็บแสดงไหม
จากนั้นเปิด `demo-compare.html` ด้วยเบราว์เซอร์

### 3. วัดผลละเอียด ออกเป็น Excel

```bash
./.venv/bin/python ml_baseline/train_eval.py \
    --data ml_baseline/PhiUSIIL_Phishing_URL_Dataset.csv \
    --flip-label --normalize-host --out ผลเทียบML.xlsx
```

ตัด `--normalize-host` ออก = รันแบบข้อมูลดิบ จะได้ผลที่ดูดีเกินจริง (ใช้แสดงปัญหาของชุดข้อมูล)

---

## ตัวเลือกสำคัญ

| ตัวเลือก | ความหมาย |
|---|---|
| `--flip-label` | **ต้องใส่เสมอกับชุด PhiUSIIL** เพราะชุดนั้นนิยาม 1 = เว็บจริง กลับกับที่สคริปต์ใช้ ลืมใส่แล้วผลจะกลับหัวโดยไม่มีอะไรฟ้อง |
| `--normalize-host` | ตัด URL ทั้งสองฝั่งให้เหลือแค่ชื่อโฮสต์ แก้ปัญหาที่ข้อมูลสองฝั่งถูกเก็บมาคนละแบบ |
| `--sample N` | สุ่มข้อมูลฝึกมาบางส่วน ให้รันเร็วขึ้นตอนลองเล่น |
| `--pause` | หยุดรอกด Enter ระหว่างขั้น (เฉพาะ `compare_demo.py`) |

---

## อยากลองแกล้งดูเอง

- `--sample 20000` แล้วเทียบกับรันเต็ม → ดูว่าข้อมูลน้อยลงทำให้แย่ลงแค่ไหน
- แก้ `RED_SCORE` ใน `analyzer/config.py` แล้วรัน `build_demo.py` ใหม่ → เส้นระบบเราในกราฟจะขยับ
- ตัด `--normalize-host` ออก → เห็นผลปลอมที่สวยเกินจริง แล้วดูว่าโมเดลไปใช้ `is_https` ตัดสิน

โมเดลไม่ได้ถูกเซฟเป็นไฟล์ ทุกครั้งที่รันจะเทรนใหม่จากข้อมูลดิบ จึงไม่มีไฟล์ลึกลับให้ต้องเชื่อ

---

## ข้อควรระวัง

- ชุดข้อมูลและชุดทดสอบมี **URL ของเว็บหลอกที่ยังทำงานอยู่จริง** อย่าคัดลอกไปเปิดเอง หน้าเว็บสาธิตทำให้กดไม่ได้และเขียน `hxxp` ไว้แล้ว
- สคริปต์ทั้งหมด**ไม่เปิดเว็บใด ๆ** ระบบถูกสั่งให้ทำงานเฉพาะชั้น 1-2 ที่วิเคราะห์จากตัวอักษรใน URL
- **อย่าเอาโมเดล ML ไปต่อเข้า `scanner.py`** จากผลที่วัดมามันเตือนเว็บจริงผิด จะทำให้ FP 0% ที่รักษามาทั้งโปรเจกต์พัง
- `ml_baseline/` แยกจาก `backend/analyzer/` โดยสิ้นเชิง ไม่กระทบเว็บ production

## ผลที่ได้ (จากการรันด้วยข้อมูลเต็ม)

จับเว็บหลอกได้กี่เปอร์เซ็นต์ ที่แต่ละระดับการเตือนผิด

| ระบบ | 0% | 2% | 6% | 10% | 20% | AUC |
|---|---|---|---|---|---|---|
| ระบบของโครงงาน | 72% | 72% | 72% | 72% | 72% | 0.860 |
| Logistic Regression | 34% | 60% | 66% | 76% | 82% | 0.866 |
| Random Forest | 0% | 0% | 20% | 40% | 94% | 0.875 |

Random Forest มี AUC สูงสุด แต่จับไม่ได้เลยที่จุดห้ามเตือนผิด
ระบบของโครงงานเหมาะกับงานที่ห้ามเตือนผิด ML เหมาะกับงานที่ยอมเตือนผิดได้

ตัวเลขนี้เป็นชั้น 1-2 เท่านั้น ปิดชั้น 3-4 และไม่ใช้บัญชีดำ เพื่อให้เห็นข้อมูลเท่ากับ ML

## ที่ยังค้างอยู่

รัน `run_eval.py` แบบครบ 4 ชั้นบน VPS ที่เน็ตปกติ เพื่อได้ตัวเลขที่แทนเว็บจริง

```bash
./.venv/bin/python run_eval.py --workers 8 --out ผลเต็ม4ชั้น.xlsx
```

เทียบกับ `--fast` จะตอบได้ว่าชั้น 3-4 เพิ่มความสามารถขึ้นเท่าไร
